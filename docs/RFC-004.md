# RFC-004: Module Interfaces (Revised)

**Project:** MCP Studio

**Version:** 2.0 (Architecture Freeze)

**Status:** Approved

---

# 1. Purpose

This RFC defines the **public interfaces** between MCP Studio modules and shared types used across the pipeline.

Parser internals are specified in RFC-005. The IR contract is defined in IR.md.

---

# 2. Design Principles

Every public module shall:

* Expose a single public interface
* Accept immutable input
* Return structured `Result<T>` output
* Never expose implementation details to other public modules

---

The **Pipeline Orchestrator** (RFC-006) wires these public modules together.

Five processing modules plus one orchestrator. Parser internals are not public.

# 4. Shared Types

```ts
interface Result<T> {
    success: boolean;
    data?: T;
    warnings: Warning[];
    errors: GenerationError[];
}

interface Warning {
    code: string;
    message: string;
    location?: string;
}

interface GenerationError {
    code: string;
    message: string;
    location?: string;
}

interface RawDocument {
    content: string;
    format: "json" | "yaml";
    source?: string;
}

interface GeneratedFile {
    path: string;
    content: string;
}

interface GeneratedFiles {
    files: GeneratedFile[];
}

interface ProjectDirectory {
    rootPath: string;
    files: GeneratedFile[];
}

interface Archive {
    buffer: Buffer;
    filename: string;
    size: number;
}

type InputSource =
    | { type: "file"; path: string }
    | { type: "string"; content: string }
    | { type: "url"; url: string };  // optional in v1; Apify uses file upload
```

`ApiModel` and IR types are defined in IR.md.

---

# 5. Loader Interface

```ts
interface Loader {
    load(source: InputSource): Promise<Result<RawDocument>>;
}
```

Responsibilities:

* Read OpenAPI JSON or YAML
* Detect format
* Return raw content

The Loader performs no validation or parsing.

---

# 6. Parser Interface

```ts
interface Parser {
    parse(document: RawDocument): Promise<Result<ApiModel>>;
}
```

The Parser is the only public module that understands OpenAPI.

Internal execution (private — see RFC-005):

```text
parse() → validate() → resolveRefs() → extract() → name() → selectResponses() → buildIR()
```

No external module may import parser internal files.

---

# 7. Parser Internal Components (Private)

Implementation lives in `src/parser/` per RFC-005 §5.

| File                 | Responsibility                    |
| -------------------- | --------------------------------- |
| `parser.ts`          | Public facade                     |
| `validator.ts`       | OpenAPI validation                |
| `resolver.ts`        | `$ref` resolution                 |
| `metadata.ts`        | ApiInfo extraction                |
| `servers.ts`         | Server selection                  |
| `authentication.ts`  | Auth scheme normalization         |
| `endpoints.ts`       | Operation extraction              |
| `schemas.ts`         | Schema normalization              |
| `responses.ts`       | Primary response selection        |
| `naming.ts`          | Endpoint id/name assignment       |
| `ir-builder.ts`      | Immutable ApiModel assembly       |

These may be unit-tested directly but must not be imported by Loader, Generators, Builder, Packager, or Orchestrator.

---

# 8. Generator Interface

```ts
interface Generator {
    generate(api: ApiModel): Promise<Result<GeneratedFiles>>;
}
```

The MCP Generator (RFC-003) is the primary implementation. It contains sub-generators internally (Tool, Auth, Client, etc.).

Future plugins (Python, Kubernetes) implement the same interface.

---

# 9. Project Builder Interface

```ts
interface ProjectBuilder {
    build(files: GeneratedFiles): Promise<Result<ProjectDirectory>>;
}
```

Responsibilities:

* Create directory structure
* Write generated files to a workspace
* Copy static templates (e.g. `tsconfig.json`)

---

# 10. Packager Interface

```ts
interface Packager {
    package(project: ProjectDirectory): Promise<Result<Archive>>;
}
```

Responsibilities:

* Compress project into a ZIP
* Preserve folder structure
* Return downloadable archive

---

# 11. Pipeline Orchestrator Interface

```ts
interface PipelineOrchestrator {
    run(input: InputSource): Promise<Result<Archive>>;
}
```

Defined in RFC-006. The orchestrator:

1. Calls Loader → Parser → Generators → Project Builder → Packager
2. Aggregates warnings and statistics
3. Returns the final ZIP or structured errors
4. Cleans up temporary workspace

Used by the Apify Actor entry point and local CLI.

---

# 12. Template Engine Interface

```ts
interface TemplateEngine {
    render(template: string, model: unknown): Promise<string>;
}
```

No knowledge of OpenAPI or MCP. Used internally by Generators.

---

# 13. Generator Helper Interfaces

Used inside the MCP Generator (not public pipeline modules):

```ts
interface SchemaConverter {
    convert(schema: Schema): JsonSchema;
}

interface AuthStrategy {
    supports(auth: Authentication): boolean;
    generate(auth: Authentication): GeneratedFile[];
}
```

`NamingStrategy` is parser-internal (RFC-005 `naming.ts`), not a generator concern.

---

# 14. Logger Interface

```ts
interface Logger {
    info(message: string): void;
    warn(message: string): void;
    error(message: string): void;
    debug(message: string): void;
}
```

All public modules accept a `Logger` via dependency injection.

---

# 15. Statistics Collector

```ts
interface Statistics {
    start(stage: string): void;
    end(stage: string): void;
    increment(metric: string, value?: number): void;
    snapshot(): Record<string, number>;
}
```

Statistics are runtime metadata. They are never written into generated source files or the IR.

---

# 16. Dependency Rules

Allowed:

```text
Orchestrator → Loader → Parser → Generators → Builder → Packager
```

Not allowed:

* Generator → Parser internals
* Generator → Loader
* Builder → Parser
* Packager → Generators (direct)
* Any module → parser internal files

---

# 17. Error Propagation

Errors propagate upward to the Orchestrator, then to the Actor/CLI, then to the user.

Modules never swallow fatal errors. Warnings are collected and returned alongside success results when generation completes.

---

# 18. Plugin Architecture

```ts
interface Plugin {
    name: string;
    generate(api: ApiModel): Promise<Result<GeneratedFiles>>;
}
```

New output formats (Python, GitHub Actions) implement `Generator` without changing the Parser or IR.

---

# 19. Interface Stability

Public interfaces in this RFC are frozen for v1.

Breaking changes require a version increment and migration notes.
